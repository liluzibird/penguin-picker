# Penguin Picker 2000

Penguin Picker 2000 is a no-cost Linux distribution and desktop recommendation MVP. It asks about a user's hardware, Linux experience, update preference, maintenance tolerance, purpose, and preferred desktop style. It then returns a distro plus a desktop environment or tiling setup, alternatives, reasons, tradeoffs, official source cards, and a live-USB checklist.

The interface is intentionally a small MVP: a plain dark page, text links, compact bordered sections, standard form controls, and simple buttons. It prioritizes a working recommendation flow over visual polish so the project can be improved later.

## AI implementation: open-source model

This GitHub Pages version runs in the browser. The only user-facing recommendation is generated by the browser-local open-source model. A small local catalog rank is supplied as context so the model can stay focused on the 26 curated distro and desktop cards; it is not shown as a substitute answer.

After the questionnaire is submitted, the app automatically loads Hugging Face Transformers.js from a public CDN and runs the instruction-tuned quantized ONNX **SmolLM2 135M Instruct MHA** model in the browser with CPU/WASM inside a Web Worker. Its tokenizer includes a chat template, so the app can send the model a real system/user instruction conversation; it also carries a plain-text prompt for browsers that need that fallback. The profile, ranked candidates, official fact cards, and prompt blueprint are sent to that model. To avoid brittle nested-JSON behavior in a very small model, the local model returns four short labeled lines. The app validates those lines and wraps the AI explanation with the verified catalog fields into the structured JSON report used by the webpage. The **LOAD LOCAL MODEL** and **GENERATE AI EXPLANATION** buttons remain available for retrying or regenerating. The first model load can take time and is cached by the browser; no WebGPU or server is required.

The shared JSON contract contains `primary_recommendation`, `desktop_or_twm`, `alternatives`, `why_it_fits`, `tradeoffs`, `live_usb_checklist`, `official_facts`, `official_sources`, and `ai_generated_explanation`. The **SHOW THE STRUCTURED JSON** panel and **COPY JSON** button make the AI output inspectable for the live demo.

Open-source runtime/model references:

- Transformers.js: https://huggingface.co/docs/transformers.js
- ONNX SmolLM2 135M Instruct MHA: https://huggingface.co/onnx-community/SmolLM2-135M-Instruct-ONNX-MHA
- SmolLM2 Instruct project/model information: https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct

The app uses three prompt-engineering patterns in a visible, reusable way:

1. **Persona Pattern:** the prompt blueprint tells an LLM to act as a cautious Linux distribution and desktop specialist.
2. **Few-shot Pattern:** three example input/output pairs show how different user profiles should be answered.
3. **Fact Check List Pattern:** the blueprint asks the model to identify factual claims that should be checked against official project documentation.

The **COPY PROMPT TO CLIPBOARD** button provides a transparent audit trail for the prompt. Because this is a browser-only MVP, the app shows a clear AI-generation error if a computer cannot download or run the model; it does not silently replace the AI report with a non-AI answer.

## Run locally

From the project folder:

~~~bash
python3 -m http.server 8000
~~~

Open http://localhost:8000 in a modern browser. Click a quick profile or fill out the form, then press **GET MY LINUX MATCH**. The app automatically loads the model and generates the only recommendation shown on the page. The first download can take time; the page shows a live elapsed-time counter for model loading and AI generation. No WebGPU setting is needed. If the download fails, confirm that you used the local server rather than opening the HTML file directly, then press **RETRY LOCAL MODEL**.

## Publish with GitHub Pages

1. Create a new GitHub repository.
2. Upload index.html, model-worker.js, and this README.md to the repository root.
3. Open Settings -> Pages.
4. Under Build and deployment, choose Deploy from a branch.
5. Select the main branch and the root folder, then save.
6. Open the generated GitHub Pages URL.

No build step, package manager, domain, server, or environment variable is needed. The AI report needs an internet connection for its first runtime/model download; after that, the browser can reuse its cache.

## Project design

This first version is deliberately limited. It has one page, one questionnaire, one transparent catalog-context rank, one browser-local open-source model, and one JSON report format. Features such as live hardware detection, accounts, user ratings, a database, and a full design system are left for future versions.

### Problem

Linux has many distributions and desktop environments. A new or returning user may not know how hardware limits, update models, maintenance expectations, and desktop workflows change the best choice.

### User flow

1. The user chooses a quick profile or answers ten short questions.
2. The app prepares a focused context from 26 curated distro + desktop/window-manager cards.
3. SmolLM2 Instruct generates the recommendation explanation locally on CPU/WASM in a background worker.
4. The app validates the explanation, wraps it into the JSON contract, and renders the recommendation overview, primary match, alternatives, tradeoffs, official facts, and hardware test checklist.
5. The user can inspect or copy the AI-generated JSON and prompt-engineering blueprint.

### Core scoring factors

- RAM and processor age
- Graphics hardware
- Linux experience
- Main purpose
- Stable, balanced, rolling, or image-based updates
- Desired maintenance level
- Traditional, modern, minimal, or tiling desktop preference
- Hardware risk tolerance
- Installation comfort

The percentage is an estimated fit score, not a performance benchmark and not a promise of compatibility.

## Limitations and next version

- The app-wrapped local AI report uses a stable JSON contract; the SmolLM2 Instruct model requires a first-time browser download and can be slower on CPU/WASM.
- If the model cannot load or produce text, the app reports that AI generation failed rather than substituting a non-AI recommendation.
- A small local model can struggle with nested JSON, so the app requests a short labeled explanation, validates it, wraps it with verified official catalog fields, and asks for a fact-check list.
- Hardware compatibility still needs a live-USB test.
- The catalog is curated rather than a live database; projects, releases, and hardware support change over time.
- Future work could add a real hardware-detection helper, user feedback, and more model choices.
